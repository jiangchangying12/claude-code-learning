精通 MCP！讓 AI 連上外部系統

作者：大嶋勇樹。MCP 是擴充 Claude Code 等代理的關鍵。本章從基礎講起，動手在 Claude Code 設定並運作 MCP，最後介紹對開發很方便的 MCP 伺服器。

3.1　MCP 入門

MCP（Model Context Protocol）是 Anthropic 提出、標準化「AI 應用程式 ↔ 外部系統」連線的協定，被喻為「AI 應用程式的 USB-C 連接埠」。

圖 3.1　MCP 的概念：用一套標準協定連接各外部系統
🔌 出現前 vs 出現後 出現前：每家連線方式各異，只有支援相同方式的組合才能連（N×M 的痛苦）。出現後：只要支援 MCP 就能互連，開發方各自支援 MCP 即可任意組合（圖 3.3/3.4）。

架構鏈（圖 3.5）：AI 應用程式（MCP 主機）→ 內含 MCP 用戶端 → 連本機/遠端 MCP 伺服器 → 連外部系統（瀏覽器、GitHub…）。

功能說明
Tools（目前主用）MCP 伺服器提供「可由模型呼叫的工具」
Resources提供給模型參照的資源
Prompts提供給模型的提示樣板
Roots / Sampling / Elicitation存取用戶端檔案系統／呼叫用戶端模型／向使用者要補充資訊

3.2　在 Claude Code 試用（Playwright MCP）

兩種設定：編輯 .mcp.json，或用 claude mcp 指令。範例（Playwright MCP，操作瀏覽器）：

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest","--browser","chromium","--isolated","--no-sandbox"]
    }
  }
}

重啟 Claude Code 會偵測到新 MCP 並請你核准啟用（選「Use this and all future MCP servers」）。之後請它「開網頁、截圖」，它會逐一請求許可（起伺服器 → 開頁 → 裝瀏覽器 → 截圖），發生錯誤時試圖自動解決是代理的一大特徵。

⚠️ 安全提醒瀏覽器操作可能把含機密的請求送往非預期網站，因此「未核准就自動操作」需特別小心。

3.3　介紹對開發很方便的 MCP 伺服器

MCP用途
Context7取得函式庫最新/特定版本文件與範例，彌補模型訓練資料的時效落差
Serena像 IDE 的符號級搜尋/重新命名/追蹤；能把支援 MCP 的 AI 應用變成程式設計代理
Chrome DevTools除了操作瀏覽器，還能做效能分析、看網路請求與 console 訊息

MCP 伺服器越來越多，已有彙整的 MCP Registry（如 GitHub 的 https://github.com/mcp）。

💡 用 MCP？還是做成指令？ 要給代理額外工具，未必非用 MCP。代理本就能執行指令，所以也可把工具做成 CLI。現成工具用 MCP；專案內的小工具，常更適合做成指令。
