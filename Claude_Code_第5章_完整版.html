活用 Claude Code Action：讓 AI 自動上工

作者：大嶋勇樹。本章把 Claude Code 放到 GitHub Actions 執行，當成「遠端型」程式設計代理。透過實際運作幾個工作流程，學會「以事件為基礎、讓 AI 先一步行動」的思維。

🎯 本章核心從「人下指令 AI 才動」進化到「事件一發生 AI 自動上工」（環境代理）——這是讓 AI 活用規模化的關鍵。

5.1　遠端型的程式設計代理

到目前為止都在本機跑 Claude Code。代理也有在遠端運作的類型——本章稱「遠端型」。最具話題的遠端型代理是 Devin。Claude Code 基底是 CLI 型，但放到 GitHub Actions 等遠端環境執行，就能像遠端型代理一樣使用。

5.2　Claude Code Action 的概要

GitHub Actions 是什麼

在 GitHub 上執行工作流程（workflow）的功能：在 .github/workflows/*.yml 放設定檔，以事件（push、issue、PR…）為觸發執行。範例：

name: Hello World
on:
  push:
    branches: [main]
jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - run: echo "Hello, world!"

on: 是觸發條件、steps: 是一連串處理（可跑指令 run: 或呼叫可重用元件 uses:）。

Claude Code Action 是什麼

它是「在 GitHub Actions 工作流程的步驟中執行 Claude Code」的 action。能輕鬆建立「以條件為觸發、執行 Claude Code」的工作流程，例如：

Issue 建立 → Claude Code 對 Issue 分類；　Issue 留言 → Claude Code 回覆；　PR 建立 → Claude Code 進行審查。

5.3　動手設定與運作

🔒 建議私有儲存庫本章會建構「Issue 一建立就自動跑 Claude Code」的機制。為避免第三者建立 Issue 觸發執行，動手實作請用私有儲存庫。

步驟：① gh auth login 完成 GitHub CLI 驗證 → ② 在 Claude Code 執行 /install-github-app，依引導安裝 Claude GitHub App、選工作流程、設定金鑰（Pro/Max 選「Create a long-lived token」）→ ③ 它會開一個 PR 來建立設定檔，合併它即完成。會建立兩個工作流程：

工作流程檔案觸發時機
Claude Code.github/workflows/claude.ymlIssue/留言/PR 審查留言含 @claude 時
Claude Code Review.github/workflows/claude-code-review.ymlPR 建立/更新時自動審查
表（圖 5.4–5.8）　兩個預設工作流程
⚠️ 與他人共用消費者條款禁止分享帳號憑證——Pro/Max 的 token 不可分享。多人共用請改用 API 金鑰，或 Amazon Bedrock / Google Vertex AI。

實際運作

寫文件：建一個 Issue，在留言打 @claude 這個交給你，Claude Code 就會啟動、更新 Issue 留言、完成任務（圖 5.9–5.13）。出問題時看 GitHub Actions 日誌（留言的「View job」或 Actions 分頁）。審查 PR：Claude Code Action 不會自動建 PR，而是給「Create PR →」連結；建立 PR 後，Claude Code Review 會自動在 PR 留下審查結果（圖 5.16–5.18）。

5.4　以事件讓 Claude Code 先一步行動

前面試了兩種：① 含 @claude 的留言下指示 ② PR 建立自動審查。前者「人不下令就不動」——要讓 AI 做大量任務時，人類指示就是瓶頸。

圖 5.19 / 5.20　環境代理（Ambient Agent）：以事件驅動，AI 比人先一步行動，必要時才請人介入
🌊 環境代理（Ambient Agent） LangChain 把「依事件運作的 AI 代理」稱為環境代理。它讓 AI 先一步行動、必要時才向人請求通知/提問/審查——突破「人類指示瓶頸」、讓 AI 活用規模化。

實作：Issue 分類（triage）

① 把官方 label-issue.md 內容存成 .claude/commands/label-issue.md（自訂斜線指令，輸入 /label-issue 即可分類）② 把官方 issue-triage.yml 存成 .github/workflows/issue-triage.yml，並把金鑰那行改成 claude_code_oauth_token。它以 issues: opened 為觸發、用 prompt 執行 /label-issue。之後新建 Issue，稍待就會自動貼上標籤（圖 5.27/5.28）。

on:
  issues:
    types: [opened]
# steps 內：
prompt: "/label-issue REPO: ${{ github.repository }} ISSUE_NUMBER ${{ github.event.issue.number }}"
🚀 延伸應用 以「事件→Claude Code Action」可對應各種業務：如 Sentry 偵測錯誤 → 自動建 GitHub Issue → 讓 Claude 一次調查原因；或用 Zapier 以各種事件觸發建 Issue。

5.5　本章小結

✅ 一句話總結用 Claude Code Action 把 Claude Code 變成「遠端型」代理；從「人下指令」改為「以事件自動觸發」，讓 AI 活用更具規模。
🧰 COLUMN：當通用代理用程式設計代理不限於軟體開發。把業務手冊與工具以 GitHub 儲存庫管理、再用 Claude Code，就能當「通用代理」處理會計、勞務等後勤業務——這已是把 AI 導入業務的現實選項之一。
