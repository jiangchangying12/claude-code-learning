將 Claude Code 整合進軟體工程

作者：吉田真吾。本章說明何謂程式設計代理（Coding Agent）、它的演進歷史，以及 Claude Code 的特徵與強項，並釐清：代理出現後，軟體工程師的工作會如何改變。核心訊息——我們不再是「對 AI 下指令然後祈禱」，而是把 AI 整合進長年累積的軟體開發方法論之中。

1.1　什麼是程式設計代理

AI 代理（AI Agent）＝針對指定目標、能自主行動以達成的系統。和傳統軟體最大差別：不必人類逐步指示，AI 會自己推論步驟、採取行動。程式設計代理就是把這套能力用在軟體開發上，是自 LLM 問世以來普及最快的代理應用。

🔑 程式設計代理的五個特徵 ① 以自然語言理解需求（從「加上登入功能」這種模糊指示理解意圖）② 自主拆解任務（大目標→可執行小任務）③ 跨多檔生成/修改且保持一致 ④ 自主使用工具（Git、npm、資料庫…）⑤ 處理錯誤（看結果、出錯自我修正）。

為何「現在」才紅？四個因素：

  • LLM 與代理技術進步：推論強、長文脈、會選用工具。
  • 工程師短缺＆成本高：軟體需求增、優秀人才難找、資深人事費漲。
  • 社會對 AI 的接受度提高、遠距工作普及。
  • 「軟體開發」本身好評估：跑得動/跑不動立刻知道、小循環、效益易感受。

1.2　程式設計代理的演進歷史

2025 年被稱為「AI 代理元年」，其中程式設計代理普及最亮眼。四個里程碑：

年份產品意義
2021GitHub Copilot程式碼補全，歷史第一步
2023CursorIDE 整合、理解整個專案、可多檔一致編輯
2024Devin遠端、全自動的「AI 軟體工程師」
2025Claude Code（＋Max 方案）CLI 型、背景非同步、Max 訂閱近乎無限用量
圖 1.1–1.4　主要產品的演進

四種類型

① 程式碼補全型（Copilot）：編輯器內行內補全，人主導。
② IDE 整合型（Cursor、Windsurf、TRAE）：對話介面整合進 IDE，理解整個專案、跨多檔編輯。
③ CLI 型（Claude Code、Gemini CLI、Codex CLI）：終端機運作，便於非同步/平行、與 CI/CD 整合。
④ 遠端型（Devin）：用 Web/Slack 互動，離開電腦也能交付。

1.3　Claude Code 的特徵與強項

💪 三大強項 ① 對規格驅動開發的適性：能從上層文件一貫展開到設計、測試、實作。
② 任務拆解能力：把「加上電商金流」拆成 設定金鑰→建資料表→建模型→實作 API→前端表單→錯誤處理→測試→更新文件。
③ 廣泛擴充性：內建工具＋MCP，並有 IDE / GitHub Actions / Slack 整合——學會 Claude Code 等於體驗代理的全貌。

此外，因使用者規模龐大，活用方法的文章/書籍多，新功能隔天就有解說，學習資源豐富。

1.4　軟體工程師的工作會如何改變

結論：工作內容會變，但不會消失。回顧歷史，抽象化層級不斷提高，每次都有人喊「程式設計師要失業」，實際只是轉向更高層次問題：

時代技術工程師的角色
1950s機器語言、組合語言直接控制硬體
1970sC 等高階語言系統程式設計
1990sJava 等物件導向抽象化程式設計
2020s程式設計代理需求定義、設計、驗證中與 AI 協作

🤖 AI 難取代、人較擅長的事 發掘商業問題、評估商業價值（該做/不該做什麼）、架構取捨判斷、品質把關、團隊協作與文化養成。AI 是提案者，人是決定者。

「會的人變得更會」：擅長把設計力、審查力化為對 AI 的具體指示與回饋的人，生產力被乘法放大——也讓擅長與不擅長者差距擴大。今後關鍵技能：對技術變化的快速學習力、AI 協作技能（控制輸出、正確評估與回饋）、系統思考與設計思考。

1.5　本章小結

✅ 三個核心 ① 程式設計代理是「能最大限度引出 LLM 能力、用於軟體開發」的 AI 代理；開發者將與它協作。
② 以規格驅動開發確實實現想做之物（PRD→設計→測試→實作→驗證，第 4 章實作）。
③ 工程師角色朝「更高層次問題解決」移動。
